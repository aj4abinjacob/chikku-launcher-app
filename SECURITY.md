# Security policy

**Project status:** working launcher foundation and private release preparation; no supported public release yet. Privacy/security contact: hello@abinjacob.in.

## Reporting vulnerabilities

Please do **not** publish exploit details, private user data or credentials in a public issue. When the repository is public, use GitHub's **private vulnerability reporting** if the maintainer enables it. If unavailable, request a private contact channel from the maintainer without including exploit details in the public request.

A maintainer should acknowledge a credible security report promptly, coordinate a fix and disclosure timeline, and publish an advisory once users can update. No response-time guarantee exists before a maintainer team is established.

## In-scope areas

- HOME role/intent abuse and exported components.
- Backup archive parsing, path traversal and data leakage.
- Work-profile and Private Space visibility.
- Notification Listener and optional accessibility/admin access.
- Widget host and icon-pack provider interactions.
- Release signing, dependency supply chain and network behavior.

## Supported versions

None yet. Once releases exist, list supported stable/beta versions and security backport policy here.

## Responsible testing

Use your own devices/accounts or explicit permission. Redact app lists, notifications, contacts and private workspace content. Do not upload real user backups to issues.
